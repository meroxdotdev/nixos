# CLAUDE.md — nixos

NixOS configuration for merox's daily driver + homelab management workstation.

## What this is

A personal NixOS system config built with Nix Flakes + Home Manager. The goal is a reproducible, declarative workstation — same philosophy as the Talos + FluxCD cluster in the `infrastructure` repo (submodule there points here).

## Repo structure

```
flake.nix              # entry point — inputs (nixpkgs, home-manager) + outputs
flake.lock             # locked input versions — always commit this
hosts/<hostname>/
  configuration.nix          # system-level: hardware, boot, networking, users, services
  hardware-configuration.nix # generated by nixos-generate-config — machine-specific
home/merox/            # Home Manager modules — user packages, shell, dotfiles, editor
modules/               # reusable NixOS / HM modules shared across hosts
secrets/               # sops-nix encrypted secrets
.sops.yaml             # SOPS config — reuses same AGE key as infrastructure repo
```

## Key decisions

- **Desktop:** GNOME
- **Secrets:** sops-nix — same AGE key file as `infrastructure/` repo, separate `.sops.yaml`
- **Inputs:** `nixos-unstable` channel
- **No mise** — tool versions managed as Nix packages; dev environments via `nix develop`

## Connections to infrastructure repo

The `infrastructure` repo (at `../infrastructure/`) manages a Talos + FluxCD Kubernetes cluster. Tools used there (kubectl, talosctl, helm, flux, k9s, age, sops, task) will be installed as Nix packages in `modules/homelab-tools.nix`.

## Apply config

```bash
sudo nixos-rebuild switch --flake .#<hostname>
```

## Conventions

- One concern per module file — don't stack unrelated things
- No inline secrets — everything through sops-nix
- Commit `flake.lock` on every `nix flake update`
- Keep modules generic enough to reuse if a second host is added later
